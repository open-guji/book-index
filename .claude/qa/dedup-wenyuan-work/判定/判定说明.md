# 任务：判定台北故宮《文淵閣四庫全書》／《四庫全書薈要》里同题 Book 挂了多个 Work 的组

背景：开源古籍库里，这两套丛书（Collection 8rlb6yi1ecqo 文淵閣、8rlb6yk66qdc 薈要）的子目 Book 有两个来源：
- 988 开头的旧 Book（早先按维基／故宫善本旧籍导入，带 vol=冊次、npm=故宫典藏号），
- 993/994 开头的新 Book（叢書线据《中國古籍總目》导入，带 juan、idx 总目著录）。
两路导入挂的 Work 不一致，于是同一题名的 Book 挂到了两三个 Work 上。每组数据里有：books（id、题名、所挂 work_id、冊次 vol、典藏号 npm、卷数、总目著录）、works（id、题名、责任者、卷数、indexed_by 著录、kind=子目新建/既有、该 Work 在这两套以外还挂几个 Book 及样例）。

你要逐组判断，输出动作。动作类型：
- `MERGE <w1>,<w2>[,...]`：这几个 Work 是同一部书（题名只是异写／加「欽定」「御定」「原本」等前缀，责任者相同或一侧缺、或是同一人的异名如 朱橚／周王橚），应并为一条。
- `REHANG <book>-><work>`：这个 Book 挂错了 Work：它挂的 Work 是同名而作者不同的另一部书，四库里这一册其实是另一个 Work 那部书。例如《春秋通論》两个 988 Book 都在第 178 冊，一个挂方苞、一个挂劉紹攽（劉書不在四库），后者应改挂方苞那条。
- `KEEP`：这套书里本来就收了两部同名异书（如《忠肅集》劉摯、傅察、于謙、盧象昇各一部；《毗陵集》獨孤及、張守），每个 Book 已挂在正确 Work 上，不动。
- `UNSURE <说明>`：信息不足或复杂（复合本、注本与原本、正续编等），不要硬判。
一组可以有多个动作，用 ` ; ` 隔开（如 `MERGE a,b ; REHANG x->c`）。

判断要点：
- 四库是否收某书、收的是谁的本子，用你的知识判断；同冊次（vol 相同）或同典藏号的两个 Book 基本是同一实物，两者应挂同一个 Work。
- 注本与白文、正编与续编、全帙与节本、两书合刊是不同的书，不要 MERGE；不确定就 UNSURE。
- 「既有」Work 在别处还挂了很多 Book 时，说明它是一部真实存在的书；若它的作者与四库这本不符，就是 REHANG 而不是 MERGE。
- 不要发明数据里没有的 id。

输出：把结果写成 TSV 文件（路径见下），每组一行，四列：`key<TAB>动作<TAB>置信(高/中/低)<TAB>理由（一句中文）`。不要表头以外的多余行；第一行写表头 `key	action	conf	reason`。写完回报行数和各动作计数。
