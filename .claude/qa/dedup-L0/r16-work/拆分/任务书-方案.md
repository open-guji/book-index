# 混条余项再核：任务书

上一轮的混条拆分里，有 23 条 Work 没有拆或只拆了一部分，见 `mixed_left.json`。每条带着当时的方案（plan：groups 每组的 Book 和著录、merges 并入目标），以及没拆的原因：
- kind=拿不准：整理者自己没把握。
- kind=复核未过：独立复核判了 WRONG 或 UNSURE，verify 里有复核理由。

方案格式、判定口径、输出格式都和 `<scratch>/SPLITBRIEF.md` 一样，请先读它。

## 你要做的
1. 逐条打开库里的原文重新核。路径：`/home/user/book-index/Work/<id倒数第3位>/<倒数第2位>/<末位>/<id>-*.json`；Book 用 `git -C /home/user/book-index grep -l '"work_id": "<id>"' -- Book` 找。
2. 有了足够证据的，写出修订后的方案：
   - 复核指出的错要改掉。例如四十二章經里两部明刻本的总目题名写着守遂注，就要随守遂注组走。
   - 并入目标卷系不合的，改为新建，或者不动。
3. 新建组要给出 `new_authors`（name、role、dynasty，有 Entity 的带 entity_id）。必要时再给 `new_title`。
4. 下面这些不拆，整组留在原 Work：
   - 选本、总集里单独收录的一卷本，例如兩宋名賢小集、宋詩鈔補、臨川文選所收的一卷。用户已定：这类作为原书的一个版本，不另立。南軒集、太乙山房集、斷腸集三条照此不拆。
   - 同一部书的不同版本，包括一卷节本对二卷全本。例如家世舊聞，节本和全本都留在原条。
5. 仍然拿不准的，写 `uncertain: true`，再写原因。不要硬拆。

- 只读库，不改任何库文件。辅助脚本放在 `r16/mix/` 下。
- 做完回报三类各多少条：可拆、不拆、仍拿不准。
