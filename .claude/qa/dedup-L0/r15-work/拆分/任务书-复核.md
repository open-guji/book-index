# 混条拆分方案独立复核：任务书

另一位整理者为若干「混条」Work（一条 Work 混进了别的书的著录、Book 或撰人）写了拆分方案。拆错会把一部书的著录挂到另一部书上，所以执行前每个动作都要你独立核一遍。只读库，不许改库文件。

方案文件结构：`works[wid].groups[]`，每组 {name, stay, books[], indexed_by[], note}；stay=true 的组留在原 Work，stay=false 的组要么并入已有 Work（见 `merges[]`: from="wid:组名", into=已有 Work id），要么新建 Work；`author_fixes[]` 是要从原 Work.authors 删掉的撰人。

库路径：`/home/user/book-index/Work/<id倒数第3位>/<倒数第2位>/<末位>/<id>-*.json`，Book 同理在 `Book/`（Book id 也按末三位分目录）。

## 你要核的（只核 mixed=true 且 uncertain 不为 true 的条目）
1. 每个 stay=false 的组：打开原 Work 原文和该组列出的 Book、著录，判断这组是否确实是**另一部书**（而不是原书的另一个版本/另一种著录写法——那种不该拆）。
2. 若该组并入已有 Work：打开 into 那条 Work，判断这组与它是否**同一部书**（同撰人、同卷系、同注释者）。
3. 若该组新建 Work：新 Work 会抄原 Work 的 authors。请写出新 Work 正确的 authors（name、role、dynasty；能在库里找到人物 Entity 的写上 entity_id，用 `git -C /home/user/book-index grep -l '"name": "某某"' -- Entity` 找，同名多人时不写 entity_id），以及正确题名（若与原题不同）。
4. 每条 author_fix：判断删得对不对。
5. stay 组是否确是原 Work 题名、撰人对应的那部书。

## 输出
TSV（无表头）到指定文件，每个动作一行，制表符分隔：
`wid	对象	判定	新authors(JSON，仅新建组填，否则空)	新题名(否则空)	理由≤60字`
- 对象：`组:<组名>` 或 `作者:<名>` 或 `stay`。
- 判定：OK／WRONG／UNSURE。拿不准就 UNSURE；只有证据清楚才给 OK。
做完回报 OK／WRONG／UNSURE 计数。辅助脚本放你自己的子目录。
