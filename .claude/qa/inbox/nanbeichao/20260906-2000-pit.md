# 坑：自寫之索引「刪鍵」函式若不循 jio 之格式偵測，會令整個分片改行距而生假衝突

本道複查八、十一併書數次，需自 `index/works/*.json` 分片刪一鍵（被併之 work）。
`jio.py` 沒有現成的「刪鍵」函式，本道自寫了一個：

```python
def remove_from_index(wid):
    for f in sorted(glob.glob(ROOT+'/index/works/*.json')):
        d=json.load(open(f))
        if wid in d:
            del d[wid]
            with open(f,'w') as fh: fh.write(json.dumps(d,ensure_ascii=False,indent=1)+'\n')
            return f
```

第一次用（批八）恰巧該分片本已是 `indent=1`＋末尾換行，無事；批十一在另外三個分片
（`4.json`／`9.json`／`d.json`）上用同一函式，這三片原是別種縮排／換行（`jio._fmt`
偵測所為），而本函式**無條件用 indent=1 覆寫**，遂令這三個約十二萬行的分片**逐行
改變縮排**——內容一字未變，diff 卻是全檔皆改。合流時三片皆撞（`git merge` 逐行比對，
縮排一變全文皆判「異」），需 `git checkout --theirs` 後用 `jio._fmt` 重新偵測格式，
只刪目標鍵，才能把 diff 收回到真正變動的那一行。

**判準／教訓**：坑 8 已言「索引分片格式不一，須用 `jio.update_index` 保留原格式」，
此坑是其推論——**任何直接寫索引分片的自製函式（增／刪／改鍵皆然）都要用
`jio.load`／`jio._fmt`／`jio.save` 三步，不得逕用 `json.dump(..., indent=1)`**。
`jio.py` 現只有 `update_index`（改鍵）而無刪鍵之對應函式，建議協調者補一
`jio.delete_from_index(family, key)`，內部走 `_fmt` 偵測，供併書、廢 entity 等
各道通用，可省下這類假衝突。

本道已用 `_fmt` 重寫更正，三片現分別只有一鍵之增減，verify 全 0。
