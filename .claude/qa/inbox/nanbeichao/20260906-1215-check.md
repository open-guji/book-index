# 新檢：索引分片之 author dynasty／role 與記錄之 authors[0] 不符（全庫 2,989 條）

`verify.py` 與 `scan.py` 之 M 類只比 `period`／`loss_status`／`title`／`subtype`（M）
與 `author` 名（verify），而索引 works 分片還載 `dynasty`／`role`（取 authors[0]）。
這兩欄改了記錄而未回寫，兩處都測不出來。

掃法（偽碼，可逕併入 scan.py 之 M 類或另立一鍵）：

```python
au = d.get('authors') or []
a0 = au[0] if au else {}
for f in ('dynasty', 'role'):
    x, y = ie.get(f), a0.get(f)
    if x is None and y is None: continue
    if x != y: report(wid, f, index=x, record=y)
```

**全庫計數（2026-09-06，origin/main 2a9e16d）**：`dynasty` 2,989 條、`role` 6 條。
其中 nanbeichao 桶 `dynasty` 142、`role` 4。

例（皆 nanbeichao，索引有值而記錄之 authors[0] 無此鍵）：
`d59f9c10irk8`（索引 南朝宋／記錄 無）、`d59f9c11rpq8`（南朝梁／無）、
`d59f9c11rpqh`、`d59f9c122y9v`、`d59f9c12e6tg`、`d59f9c12pfd2`。
`d59f9c*` 一族是 2026-09-06 新入之《補南北史藝文志》條，成群出現，疑是匯入時
索引與記錄兩路各自成形（PITFALLS〈同前綴的問題往往成群〉）。

另一來源是 2026-09-05「泛稱 entity 解繫」：撰人作「某氏」者撤其 entity 與其代，
記錄側撤了而索引側未撤。例：`d59f286rscg2` 江圖（索引 dynasty「南朝宋」，
記錄 authors[0]「張氏」已無 dynasty）——本道已於批二隨手去之。

**要協調者定的一件**：這 2,989 條該以哪一側為真？
記錄側為真（去索引之值）只在「解繫／撤代」型是對的；`d59f9c*` 那一族若是
匯入時記錄側漏寫，反而該由索引回填記錄。二者混在一個計數裡，宜先按 id 前綴
與 ai_note 分族再定，不宜一刀切。本道只動了自己批次所及之一條，餘 141 條未動。
