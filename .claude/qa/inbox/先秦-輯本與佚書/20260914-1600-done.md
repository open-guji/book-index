## 七、下一道要知道的（坑，點名）

1. **book-text 倉輯佚檔之路徑**：`ai_note` 裡寫的「Work/1/e/v/…」形式路徑是
   **舊的、已失效**的（可能是某次 ID 遷移前的內部路徑）。現行路徑一律用
   book-index 現行 `work_id` 直接查：
   `book-text/Work/<work_id尾三字符逐字>/<work_id>/fragments/*.json`。
   若信了 `ai_note` 裡的舊路徑去找檔案，會一無所獲而誤判「查無輯佚檔」。
2. **本環境（Claude Code on the web／雲端）無 `book_index_manager`**
   （Windows 專用工具，`D:/workspace/book-index-manager`）。ID 生成、
   `qa_book.py`／`check_promote_book.py` 需另 `add_repo` 並 clone
   `open-guji/book-index-manager`，設 `BOOK_INDEX_MANAGER=<path>` 環境變數
   方可用；否則只能手工按《索引ID.md》64-bit Snowflake 規則自行實現生成器
   （本道即如此，見 `verdicts.py`／`idgen.py` 附本道 inbox）。
3. **`reindex.py --membership` 只認 `Work`／`Entity`，不維護
   `index/books/`**——新建 Book 後光跑 `reindex.py` 不會補 Book 索引鍵，
   `verify.py --strict` 之「work 側懸空引用」會非零。須手動：算好
   `shard(id)`（`h=h*31+ord(c)` 逐字後 mod 16），用 `jio.load`／`jio.save`
   （**不要直接 `json.dump` 整檔重寫**——`indent` 猜錯會把上萬行判成
   改動的假 diff，本道自己就在這上面栽了一次，發現後補了一個修正提交）
   補鍵。
4. **`add_repo` 預設只給讀權限**——clone 下來能改能 commit，但
   `git push` 會被 proxy 硬拒（`403 access denied by the git proxy`），
   且 `pushmain.sh` 會把這個 403 誤報成「推 main 被拒，重合流」，重試
   三輪後放棄，看起來很像撞了別人的並發推送，其實是壓根沒有推送授權。
   遇到這個現象先查 `git push` 的原始錯誤訊息，是 403 就去補
   `add_repo(..., access="push")`，不要一直重跑 `pushmain.sh`。
5. **並發合流的實測**：與同日在跑的「先秦-出土單篇道」「先秦-條目收尾道」
   「先秦-傳世版本道」在 7 個 Work 檔上撞了 `ai_note` 併發追加——全部只是
   「雙方各自在 ai_note 末尾加一段」的純追加式衝突，用「取自身版本為底，
   把對方的新增段接在後面」即可正確三方合併，沒有一處是真正語義互斥的
   衝突。三方比對（base／ours/HEAD／theirs）後發現：**除 ai_note 外，其餘
   6 個衝突檔的其他欄位分歧都各自落在對方字段族**
   （`authors`／`juan_count`／`measures`／`indexed_by` 全歸「先秦-條目收尾」
   一側），本道字段（`loss_status_note`／`books`）全歸本道一側，
   驗證了任務書 §四·2 之字段族劃分在實測中確實不撞車。
