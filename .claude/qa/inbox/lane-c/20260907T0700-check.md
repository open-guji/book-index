這一批做的是**回頭核自己**——判準立得快，就更該自己找它會錯在哪。

## 一、自核之法與結果

拿本道所落的 **856 筆 C `normal`**，逐條取其 work 之 `indexed_by[].author_info`
**首之朝代字**（志書原文之題署，一手）與該 entity 之 `dynasty` 相比，不同桶者 132 條。
逐條讀完，**沒有一條是本道判錯**。132 條分兩類：

**（甲）跨代之人，兩說皆通**——四庫題「明董說撰」而 entity 作「清」、題「宋熊禾撰」而 entity 作「元」之類。
work 之 period 與志題相合，本道所判者正是 work 之 period，故判無誤；
惟 entity 之單代確可收窄（見下第二節）。

**（乙）本道自核用的那把尺自己讀錯了**——三型，記之以免他人重蹈：
1. **姓氏被當成朝代**：《國史經籍志》作「**陳**則通。」「**周**應」——陳、周是姓。
2. **年號被當成朝代**：《補遼金元藝文志》「**明昌**六年，禮部尚書張瑋等進」——明昌是**金章宗**年號，不是明朝。
3. **多撰人並列而取了首一人之代**：《書目答問》「**漢**毛亨傳、鄭玄箋、**唐孔穎達**正義」——
   我拿「漢」去比孔穎達。同型者《山中白雲詞疏證》「(宋)張炎撰(清)江昱疏證」、
   《主客圖附圖考》「(唐)張為撰(清)袁甯珍撰」。

**這三型合起來，正是坑 51 說「機械抽人名／抽朝代分不開」的同一個病**——
本道只是拿它做自核之尺（錯了不落賬、只是多讀幾條），不是拿它立檢；若要立檢，這 132 條裡約三成是噪音。

## 二、順手出的一張可辦之表：**51 人之 entity 可據一手著錄收窄為跨代稱**

`known-issues/lane-c-20260907-entity跨代稱可收窄五十一人.json`。
明末清初 31、宋末元初 11、清末民初 6、元末明初 3。四十人有自載生卒相佐，十一人止據著錄之文。

**這正對著本道所報之最大成因**——1,154 條裡逾七百條是「跨代之人被壓成單代」。
惟須說明白：**收窄 entity 未必能消 C 之報**（「宋末元初」仍落 liao-jin-yuan 桶，與 song 之書仍相牴），
**此表之用在資料之真，不在消報**。且依坑 62，**只改 entity 之 dynasty，一條 work 之 period 都不要動**。
