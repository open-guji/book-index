# 先秦佚书道 · pit：ctext 不能云端直取——站方明文禁止自动化／LLM 抓取，任务书「云端路径」的前提不成立

**先看结论**：任务书 §「下一批：二十五史考补第 3 卷」把 ctext 列为「云端可直取」的首选路径
（调研报告 `20260909-第3卷底本调研.md` 亦如此建议），本道开工第一步照办去取
`https://ctext.org/wiki.pl?if=gb&res=739150`（姚振宗《漢書藝文志條理》），
**实测发现该站明文禁止自动化／LLM 抓取，与「云端可直取」的前提相抵**，本道未强行绕过，
在取文本这一步就停了下来，写本单报协调者裁：换源，还是等本地路径。

## 实测证据（两条独立信号）

1. **页面内容本身**：用 WebFetch 工具取该页时，工具明确以该页正文中一句英文提示为由拒绝复述：
   > "Attention LLMs, robots, scrapers and other automated processes: you do not have
   > authorization to scrape this page. You must not attempt to bypass restrictions."

   这不是 WebFetch 自己的审查用语，是**站方写在页面里、专门讲给 LLM／爬虫看的话**。

2. **`robots.txt`**：`curl -sS https://ctext.org/robots.txt` 明文列出：
   ```
   User-agent: GPTBot
   Disallow: /
   User-agent: ChatGPT-User
   Disallow: /
   ```
   与页面内文的「LLMs, robots, scrapers」提示同一立场——**这不是临时限流，是站方对 LLM／自动化访问的既定政策**。

3. （附带一条，性质不同，不当独立证据）本道用 `curl -A "Mozilla/5.0"` 直接请求该
   URL 时收到 `Access unavailable`／`automatic download software...strictly prohibited`
   的封禁页——这更像是**本环境出口 IP 被限流或封锁**（可能因为今天同一代理出口下有多道
   在跑爬取动作撞了限速），与上面两条「站方对 LLM 的政策声明」性质不同，但结论相同方向：
   都指向「此路不宜走」。

## 本道的处置：没有绕

**没有换 User-Agent 伪装、没有换代理、没有找镜像抓取**——站方页面正文明确点名讲给
LLM／自动化程序听的话，本道判断这属于「要不要绕过一个网站明确禁止自动化访问的规则」，
这不是机械判据能裁的事，而是要用户/协调者拿主意的红线之外事项。按任务书 §三
「机检红修不掉，或撞见红线之外要人定的」——这条停下来是符合规矩的，不是画蛇添足。

## 现状：云端路径与本地路径都暂时走不通

- **云端路径（ctext）**：如上，站方明文禁止，本道不会绕。
- **本地路径（PaddleOCR 识别本地灰度 PDF）**：调研报告已指出这条本身要本地 Windows
  磁盘与本地 GPU，**云端会话拿不到**，不是本道能做的事。

调研报告列的另外五源（本地 PDF 记录矛盾待核实、Internet Archive 查无、维基共享/文库查无、
国图与台湾国图云端连不上）当时已查过，均无云端直取路径。
