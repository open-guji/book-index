# scan.py 之 M 報信鍵撞號——索引漂移舊檢與坑43新檢共用一鍵（suitang 道）

## 一、錯在哪

`scan.py` 有兩處各自獨立的 `R['M'].append(...)`：

- 約 319 行：舊有之「索引 vs 記錄欄位漂移」檢，列項為 `field`／`index`／`record`。
- 約 599 行：坑43 新立之「loss_status 與 description 互不覆核」檢，列項為 `kind`／`loss_status`／`evidence`。

兩檢邏輯全不相干，卻共寫 `R['M']`，同一報信鍵下混入兩種不同 schema 之列。逐道批次腳本若假設
`d['M']` 全為坑43之型（如逐條讀 `r['evidence']`），一旦該道當輪恰有索引漂移之列混入，即
`KeyError`；縱不炸，亦難辨此列究竟屬何檢。

## 二、驗證

`grep -n "R\['M'\]" .claude/qa/scan.py` 只得此二處，別無他鍵重複。本道批18（loss_status 補全
232 條）取用之際恰無索引漂移之列混入，未炸，但屬僥倖，非幸無此坑。

## 三、建議

坑43新檢改用未占之字母（如尚空之 `N` 或別擇一未用者），或索引漂移舊檢併入既有之
`verify.py`「works 索引漂移」項（該項本已存在，`scan.py` 內或屬冗餘）。何者為宜，請協調者定奪；
本道僅報坑，不代改 `scan.py`（依規程，共用工具不逕改）。
