# 併書後照 merge_history 改 Entity.works，不看 Work 側 authors 指誰，會留單向邊

三次合流連遇四例，成因相同，記在此處免得清賬（三）再犯。

## 怎麼發生的

C 層清賬併同書異條時，source work 刪，target 記 merge_history。隨後補 Entity.works
的腳本按 merge_history 把指向 source 的邊改繫 target——**但沒查 target 之
authors[].entity_id 是不是這個 entity**。若那部書併入之後撰人歸了別人，就成了
一條單向邊：人指書，書不指人。verify.py 查不出（它只查懸空與索引漂移）。

## 四例

| entity | 改繫到 | 而該書撰人實是 |
|---|---|---|
| 王邵（唐，卒 784） | 《開皇二十年書目》 | 王劭（隋）`hixhd2h9bn8m` |
| 葉文 | 《菉竹堂書目》 | 葉盛 `hixhd2h9bebm` |
| 王文 | 《王文莊書目》 | 王鴻儒 |
| 丁丙藏 | 《八千卷樓書目》 | `92qfvz17vg7k` |

後三例的 entity 本身就是撰人書名切分之誤所生的假人：
「葉文莊公菉竹堂書目」誤切作撰人「葉文」＋題「莊公菉竹堂書目」；
「王文莊書目⟨王鴻儒⟩」誤切作「王文」＋「莊書目」；
「清丁丙藏編」之「藏」屬動詞，誤切作「丁丙藏」＋「樓書目」。
王邵／王劭則疑本一人異寫（隋史官王劭亦作王邵），屬 E3 正名異體重出。

## 改法

改繫之前先看 target 之 authors 有無本 entity：

```python
tgt_owners = {a.get('entity_id') for a in (target.get('authors') or [])}
if eid in tgt_owners:      改繫
elif tgt_id in have:       去重（本條已有其繫）
else:                      摘，ai_note 記明那書已歸誰名下   # ← 漏的是這一支
```

已依此摘去四條，各記 ai_note 可逆。
