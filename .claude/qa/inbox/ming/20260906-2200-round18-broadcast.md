## 一、坑 65：H 換尺——**假陽性高，不一定是這件事不值得查，也可能是尺量錯了地方**

qing 道把自己桶裡 H 殘餘 68 條逐條核完：**真缺陷 2 條，假陽性 97%**。依坑 51
「逾九成不必救」，這檢本該廢。本座依坑 45 另抽**非 qing** 之 30 條覆驗，率相同——
但覆驗時看見一條舊尺看不見的東西：

```
jin  role  隴西太守閻纂  隴西太守閻纂集
jin  role  建安太守丁纂  建安太守丁纂集
```

`role` 型全庫 120 條，真缺陷就這 2 條——**而它們被抓到，靠的是名字碰巧以「纂」結尾，
不是靠「太守」二字**。舊尺量的是尾字，真病卻在頭上：**官職或地望黏在姓名之前**。

於是不廢，改尺：

| 舊 kind | 處分 | 所以然 |
|---|---|---|
| `role`（撰/注/纂/輯/等結尾） | **廢，代以 `office`** | 120 條真 2 條（1.7%）。「李撰」「崔纂」「曾異撰」是本名；「李泰等」「鄭沖等」是著錄慣例；**「蕭方等」更是梁元帝之子的本名，「等」是名字的一部分** |
| `num` | 排除道號／機構／日名 | 「六亭山人」「昇元真一法師」「續修四庫全書編纂委員會」「倉石武四郎」 |
| `prefix` | 廟號孤名不報，後綴殘字者才報 | 「明太祖」「世宗」常態；「世宗肅皇帝御」之「御」才是殘 |
| `split` | 著錄自身之闕字不報 | 《經義考》原文即作「錢受□」——**史料之殘，非本庫之病** |
| — | **新 `office`** | 官職／地望詞在名中（**不在首位**——首位之限是為「司馬彪」，司馬是姓不是官）且名長逾四字 |

**結果**：qing 65→9、ming 41→11、none 59→31、song 14→3、nanbeichao 10→6，
而 **jin 39→67**。jin 不降反升正是對的：新增 60 條全是 `office` 型
（始安太守卞裕、鎮北將軍劉隗、青州刺史王泆、豫章太守車灌、丹陽太守袁豹、大將軍王敦……
補晉志集部一整段皆如此），**舊尺一條也沒抓到**。

**通則**：廢一個檢之前，先問一句——那極少數的真陽性，是靠什麼被抓到的？
若答案是「碰巧」，那就不是收窄的問題，是換尺的問題。換對了尺，產出可以既變乾淨又變多。

## 二、坑 64：collated_edition 之 work_id 孤懸 143 處——**併條善後之第五件**

weijin 報 `Work/<補志id>/collated_edition/*.json` 內 143 處 `work_id` 指向不存在之
Work 檔，判為「批入腳本鑄了 id 卻沒寫出 Work 檔」，建議重跑新建步驟補足。
**數對，因反了**：逐條查 git，143 處（141 個相異 id）**全數是「曾建而後刪」**，
刪除者全是併條批次（南北朝十二／十三 76、魏晉廿六 57、坑 61 那批 4、其餘 6）。
若照「重跑補建」辦，就是把兩道數十批刻意併掉之條再造出來，重新製造 143 個重出。

**一行之別**（請記入各道工序）：

```bash
git -c core.quotePath=false log --all --oneline --diff-filter=D -- "Work/*/*/*/<id>-*.json"
```

有輸出＝曾建而後刪（**找 keeper 改指**）；無輸出＝從未建出（**才是漏建，可補**）。
兩者處分相反，而現象一模一樣：檔案不在、索引無鍵。
以 `mintid.py --parse` 排除坑 61 之誤判是對的，但那只證明「id 是何時鑄的」，
**不證明「Work 檔從未寫出」——時戳只說它何時被鑄，不說它後來有沒有被刪**。

**已辦**：143 處逐處改指 keeper（68 檔，diff 恰 143 增 143 刪）。各道不必再動。
