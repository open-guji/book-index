### B. `DYNASTY_MAP` 漏了两个码位——**这是实测踩出来的，会静默漏配**

1. **`漢→{2,29,46,83,25}` 漏了 52。**
   `c_dy=52`「後漢」在 `DYNASTIES` 里标 947~951（五代後漢），**装的却是大批東漢／漢末人**：
   寇恂、馮異、李膺、袁紹、鍾繇、皇甫嵩、陶謙、賈詡、張郃、曹仁、劉表、張魯……
   **41 人可由同库同名条目自证**（馮異 462585 ↔ 30683[東漢]、賈詡 498394 ↔ 11723[三國魏]…）。
   → 用现有 map 预筛東漢人，**躲在 52 里的一律漏掉**。我方已有 8 条挂在 52 上被判年代冲突。

2. **`周→{1,2,61}` 漏了 77。**
   `c_dy=77` 才是「周」（武周 684~705，461 人）；`c_dy=1` 是漢前（skill 速查表已警告这点）。
   我方 6 条 `dynasty=「周」` 的条目（索禮、閻朝隱、路敬淳、喬知之、杜元志、楊元亨）
   **正是从 `c_dy=77` 回填的武周唐人**，生卒 640~712。用现有 map 预筛，这批永远匹配不上。

> 附带一条给所有下游的判准：**「周」在我方数据里姬周／武周同形，不可凭字面断代。**
> 本道一开始按字面把这 6 条归进先秦，先秦段分母直接错了 6 条，靠 `dynasty_basis` 里
> 那句「CBDB c_dy=77」才发现。判据优先级应为 `period` > 实年 > **无歧义的** dynasty 字面。

### C.「CBDB 全繁体」这个假设不成立

skill 陷阱库：「CBDB 全繁体。若输入疑似简体，应先转繁。」
**实测 CBDB 侧本身混有简体字形**——`BIOG_MAIN` 正名如 135189「臧孙辰」、339510「嬴子婴」；
`ALTNAME_DATA` 有 4,534 条含简体字形（「东皋老人」「丹语」「个山」）。
→ **应双向归一**，只单向转繁会漏。

## 乙、判准可加强的（D–G，本道都有实测与现成代码）

### D. 异体字表不够，opencc **不管用**于最高频的那批

skill 用 `CHAR_VARIANTS`（约 20 对）＋ 转繁。实测 **opencc `t2s` 不处理**：

```
飜/翻 ✗   曽/曾 ✗   勗/勖 ✗   徳/德 ✗   凖/準 ✗   郞/郎 ✗   鄶/㮮 ✗
（它管用的是繁简对应那类：顔/顏 ✓  嶽/岳 ✓  臺/台 ✓  温/溫 ✓）
```

漏掉的后果是实打实的——查 0 命中而 CBDB 明明有：
虞飜→**虞翻 423302**、徐師曽→**徐師曾 129943**、朱睦鄶挈→**朱睦㮮 127365**、
張德盛→**張徳盛 400737**、王若虗→**王若虛 29507**。

→ 本道建了 **423 字**的异体表 `overview/scripts/cbdb-survey/variants.py`，
判据是「两名等长且差异位**全部**互为异体」，实测能正确排除「李雲鸞 vs 李雲鶴」这类不同人。
**可直接并进 skill 的 `CHAR_VARIANTS`。**

> ⚠️ 反面教训：不要用 opencc `s2t` 的可逆性去机械判简体——「范」「岳」「采」「臺」「徵」
> 在繁体中本就是本字，一对多映射会过度转换。本道曾据此得 22,315 条，**判据不可靠，已弃用**。

### E. 前缀剥离要加两道闸，且**绝不能用单字前缀**

skill：「僧/釋 前缀已修复（`_score_candidate` 剥离前缀后比对）」。实测这么做有假阳：
「釋明成」剥成「明成」匹配到**俗人張位的字号**、「僧文瑩」→「文瑩」匹配到宋子環。

→ **剥后须两道闸**：只认 `name_chn` 命中（**不认 altname**）＋ 年代相容。
加闸后本道的前缀命中从 205 条降到 13 条，剩下的（道士陳性定→陳性定[元]、
道士劉大彬→劉大彬[元]、吳興太守孔嚴→孔嚴[東晉]）逐条看过都对。

→ **单字前缀一律不可用**：「王應山」→「應山」、「公孫龍」→「孫龍」、
「司馬無忌」→「無忌」（東晉宗室，司馬是姓不是官）全废。
**姓氏与前缀同形，单字分不开，只能靠「前缀 ≥2 字」这条硬规矩挡住。**

### F. `NON_PERSON` 过滤要扩，但单字后缀会误伤

skill 只硬过滤「不詳／佚名／撰人不詳」。实测还须滤：
机构（步軍統領衙門）、神祇（樟童帝君＝梓潼帝君、許真君、馬鳴菩薩、劉谷神）、
单字名、七字以上断句未净（罽賓僧伽跋澄譯、優婆塞衛士度譯）。

⚠️ **机构判据别用单字后缀**：本道用 `會$` 把「胡會」判成了机构。
须要求名长 ≥4，或只认多字机构词（衙門／書院／國子監）。

### G. `auto_create` 这一路的判准建议整体复查

我方 117 条「CBDB 侧姓名不在我方任何名字里」中 **52 条来自 `auto_create`**，形态一律是前缀撞：
沈孟操→「沈孟」411795、沈之琰→「沈之」631638、汪顯徳→「汪顯」411656、
梁應圻→「梁應」409005、李希雄→「李希」453497、施弘猷→「施弘」404071、盛鳴世→「盛鳴」416467。

> **本道自己在这里栽过一跤，记下来免得下道重蹈**：一度把 CBDB 的「沈孟」「汪顯」
> 判成 **CBDB 的截断名缺陷**，核 `c_surname_chn`／`c_mingzi_chn`／拼音后发现分解完整，
> **本来就是二字名的人**——是我方拿前缀去撞的。**差点把我方的错报成 CBDB 的错。**

skill 的 schema 一节只列了 `auto／manual／pending／none`，**未提 `auto_create`**，宜补上并写清判准。

## 丙、本道与 skill 的分工（不是出入，是各管一段）

### H. 本道查法**多覆盖两处人名来源**，建议 skill 也加

skill 只查 `BIOG_MAIN.c_name_chn` ＋ `ALTNAME_DATA.c_alt_name_chn`。本道穷举 78 张表后另加：

- `c_surname_chn ‖ c_mingzi_chn` 拼接（**1,550 条与正名不同**）
- `c_name_proper / c_mingzi_proper` 译名正字（**9,534 条**，多为蒙元、西人）

### I. 本道**没用**著作重合信号，那是 skill 的强项，B 组下一步就该用它

skill 的 `work_recall`（`BIOG_TEXT_DATA`／`TEXT_CODES`）是消歧主力，**本道完全没用**——
因为本道要答的是「CBDB 有没有这个人」，不是「查得到的这个是不是同一人」。

但**普查留下的 B 组 2,957 条（未挂而有年代相容同名者）恰恰要答后一个问题**，
`work_recall` 是现成的正解。**建议下一道直接用 skill 跑 B 组，不要重新发明。**

### J. 建索引 vs 内存索引，两种做法适用场景不同

skill／方案档 §8.2 说「先建五个 sqlite 索引，否则慢一个数量级」——对，逐条查询时确实如此。
本道做的是**全库对撞**，改为一次性把 66 万个名字读进内存建 dict 索引（**25 秒**，
582,958 字面键＋577,445 归一键），30,827 条对撞 1 分钟跑完，没建 sqlite 索引。
两种做法并存即可，宜在 skill 里注明「逐条查用 sqlite 索引，全库对撞用内存索引」。
