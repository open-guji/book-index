# ask：`pushmain.sh` 對非索引衝突默認 `--ours`，與鐵律 2 相牴，多道已各踩一次

- 道：`先秦-傳世版本`　日期：2026-09-14
- 性質：**共用工具的規格問題**。工具凍結、只協調者可改，故提規格不自己動手。

## 一、事實

`pushmain.sh` `resolve_conflicts()` 對非 `index/` 路徑一律：

```bash
*)  echo "非索引衝突，取己方：$f"; git checkout --ours -- "$f" ;;
```

而[任務書模板](../../../../overview/項目進展/古籍索引網站/調度/任務書模板.md) §四 鐵律 2 寫的是：

> **條目檔衝突不許 `--ours`。**先看對方改的是不是你的字段族；不是就停下報協調者。

**腳本的默認行為，正是鐵律明令禁止的那一件。**而且它只 `echo` 一行就過去了，
不中止、不非零退出——一眼掃過去很容易當成正常日誌。

## 二、今天已經發生兩次，兩次都真丟了東西

| 次 | 檔 | 誰丟了誰 | 結果 |
|---|---|---|---|
| 1 | `Work/.../d59f2evu42rm-野老.json` | 他道丟本道 | 本道 2026-09-14 加的 `resources`（維基共享玉函山房影像）整段被覆蓋。他道自己發現並手工三方合併修回，見 commit `d2b10fb820` |
| 2 | `Work/m/0/w/d59f1ioc6m0w-周禮.json` | **本道丟丁道** | 丁道 `3132f704fd` 的兩處改動被本道覆蓋：`related_works[].title`「…原目」→「…原目一卷」（audit_classic 報的題名不符，丁道已訂正）與 `ai_note` 的相應追記。本道發現後已以對方為底重新合併，只疊回自己的 `resources` |

兩次形狀完全一樣：**兩道各改各的字段族，本不該衝突，是 git 行級合併把相鄰字段判成撞行**
（調度 README §二 早就點出「JSON 相鄰字段撞行不是小概率事件」）。腳本一 `--ours`，
後推的那一道就把先推的那一道抹掉，而且**雙方都不會收到任何告警**。

## 三、建議的規格（三選一，本道傾向甲）

**甲（傾向）**：非索引衝突一律**中止**，不自動解。印出衝突檔清單與「請人三方合併」，
非零退出。理由：這正是鐵律 2 所要的行為，且丟數據的代價遠高於多推一輪。

**乙**：非索引衝突走**字段級三方合併**——`git show :1:$f`（base）／`:2:`（ours）／`:3:`（theirs）
三方載成 JSON，逐頂層鍵比對：只有一方改過的鍵取那一方，兩方都改過同一鍵才中止報人。
本道今天手工做的正是這個，兩次都能無損。JSON 一檔一條目，這個做法對本庫特別合用。

**丙（至少要做）**：保持現行行為，但把 `echo` 改成**醒目告警＋把被覆蓋的對方版本存檔**
（如 `git show :3:$f > .claude/qa/conflicts/<檔名>.theirs.json`），並在結尾匯總
「本次覆蓋了 N 個條目檔，請覆核」，非零退出。

## 四、另請協調者做的一件事

請掃一遍今日各道的 pushmain 日誌，凡有「非索引衝突，取己方」字樣的，逐檔覆核。
今天四道並行、都在改先秦這一片條目，**撞車面比平時大得多**；
已知的兩次都是人事後發現的，沒發現的未必沒有。
