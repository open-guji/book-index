# ask：建 Book 撞上三處工具缺口，皆已繞過，提規格請協調者定奪

- 道：`先秦-傳世版本`　日期：2026-09-14
- 背景：判據 4 要為「無 Book 而傳世有版本」之條建版本條目，共建 5 個 Book。
  **三個共用工具都只認 Work 而不認 Book**——工具凍結，故一律只繞過不改，提規格於此。

## 一、`mintid.py` 鑄 Book id 直接中止

```
$ python3 .claude/qa/mintid.py --type Book --lane shanggu -n 5
鑄出之 id 非 12 位（98jhzlk6ww），時戳或有異，中止
```

**根因**：`mint()` 末尾 `if len(i) != 12: raise SystemExit(...)`。
而 Book 之 type 位編碼為 **0**（`TYPE = {0:"Book", 2:"Collection", 3:"Work", 4:"Entity"}`），
`raw = (0<<59) | ...` 少了高位，base36 恆為 **10 位**。
庫中規範 Book id 皆 10 位，以該檔自己的 `--parse` 驗之即明：

```
988g96wyko  Book  Official  ts=2026-08-25T23:55:54(s)  machine=1  seq=8
```

**建議**：長度校驗按型分——Book 10 位，Work／Collection／Entity 12 位。

**本道之繞法**：只複用 `mintid.b36()`／`_existing_ids()`／`parse()`，自行組 raw 並改驗 10 位，
鑄出 `98ji05um80`–`84`，逐個 `--parse` 回驗 type=Book 無誤。

**另請分配 machine id**：`LANE_MACHINE` 只有協調者 2000 與九道 2001–2009，
本輪先秦四道皆不在表中。本道暫借 `shanggu`＝2001（先秦屬上古，語義最近），
**請協調者確認或改派**，並把先秦收官四道補進表裡，免得四道相撞。

## 二、`reindex.py` 完全不管 Book——新建 Book 必然懸空

`scan_files()` 只掃 `('Work', 'Entity')`；且 `REC_RE = r'^[0-9a-z]{12,13}-'`
要求 12–13 位，**Book 的 10 位 id 根本不匹配**。故建完 Book 跑
`reindex.py --run --membership` 報「已補鍵 0」，而 `verify.py --strict` 立刻紅：

```
work 側懸空引用       5
  懸空 ('d59f2evs8ni8', 'books', '98ji05um80')   …（5 條全是新建的 Book）
FAIL
```

`index/books/*.json` 是誰維護的？看來是上游 `book-index-manager`，
而云端各道取不到那套生成器——**於是雲端道實際上無法建 Book**，這條路是斷的。

**建議**：`reindex.py` 增 Book 一支（`scan_files` 加 `'Book'`，`REC_RE` 放寬到 10 位）。
欄位生成規則本道已自既有索引條目逆推並抽樣驗過，可直接用：

```
id/title/type/path/edition/work_id 恆有
author←authors[0].name   role←authors[0].role   dynasty←authors[0].dynasty
era←dating.era           sort_year←dating.year  holder←current_location.name
juan_count←juan_count.number
has_image←resources 任一 types 含 image
**值為空者不寫該鍵**（非寫 null）
```

**本道之繞法**：照上表寫了 `reindex_books.py`（冪等，附於 done 單），
補完 `verify.py --strict` 全綠、懸空歸 0。該腳本可直接併入 `reindex.py`。

## 三、`qa_book.py` 的 Official Book 前綴表過時

```
[WARN] ID04  前缀 98 不在 Official Book 已知前缀 ('96', '97')
```

**實測庫中 Book id 前綴分佈**：

| 前綴 | 個數 |
|---|---:|
| **98** | **20,791** |
| 96 | 53 |
| 其他（fa/zd/z7/z5/yz/y3…各 1） | 早期不規範之隨機串 |

**98 佔 99.7%**，而表裡寫的是 `('96','97')`——97 一個都沒有，98 反倒不在表中。
建議把 `TYPE_PREFIX_*` 改為以 `mintid.parse()` 之 type 位判型，不再維護前綴白名單
（前綴隨時戳推移必然漂移，白名單注定過時）。

## 四、附帶一件：庫中有 id 形態不合規的舊 Book

`--parse` 順手驗出幾條時戳荒謬者，非本道所建，僅報備：

```

zdiwtiilsg  Book  ts=2187-02-24  machine=676
```
