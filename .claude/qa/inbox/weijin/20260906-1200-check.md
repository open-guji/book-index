# 新檢：entity 訂正之後，work 之 authors[].dynasty 未隨改（entity_propagation 之殘值）

scan 之 C 類比的是 entity.period 與 work.period，A 類比的是 period_basis 與 authors[].dynasty，
二者之間漏了一格：**work.authors[i].dynasty 與其所繫 entity.dynasty 相牴**。
此格所以要緊，是因為早期諸輪以 `entity_propagation` / `entity_propagation_r2` 把 entity 之代寫進 work 之
authors[].dynasty；其後 entity 之代被訂正（如 2026-08-19「重複人物 entity 專項」拆同名異代者），
而 work 側之殘值無人回收，於是「entity 已作晉，而其書之撰人欄猶作明」。
description 之「某某（明）撰」亦自該欄機生，一併帶錯。

例（本道所見，皆已修）：
- `d59f27wqbjep` 析言論、`d59f27wog45e` 逸民傳：authors[0].dynasty「明」，
  而 entity `hixhd2h9bnv1` 張顯早於 2026-08-19 由「明」正為「晉」（拆分案語自書「晉張顯。與明張顯（生 1452）同名異代」）。
  同 entity 名下第三書《古今訓》`d59f27vhdd6o` 之 authors 已作「晉」——**同一 entity 名下之 work，
  有的隨改有的沒隨改**，是此類之徵候。
- `d59f27x5m60w` 靈棋經 題：authors[1] 何承天「晉」，而 entity `hixhd2h9bmxx` 作「南朝宋」（370–447，CBDB 497216）。

掃法（偽碼）：

```python
for w in works:
    for a in w.get('authors', []):
        eid = a.get('entity_id')
        if not eid or 'dynasty' not in a: continue
        ed = ENT[eid].get('dynasty')
        if ed and a['dynasty'] != ed:
            # 正規化之後仍異者才報：晉⊃西晉/東晉、宋⊃北宋/南宋、漢⊃西漢/東漢、
            # 三國⊃三國魏/蜀/吳，粗細相容者不算
            if not compatible(a['dynasty'], ed): report(w, a, ed)
```

**須先正規化再比**（SKILL〈表層計數不是缺陷之證據〉之「雙向查驗俱須正規化」）：
只比字面則「晉 vs 西晉」滿屏假陽性，本道 A 類 792 條中 764 條正是此形。
建議報表另立一鍵（如 `O author_dyn_vs_entity`），並在明細裡帶上
`a.get('dynasty_basis')` ——凡值以 `entity_propagation` 起首者，即此病之確證。
