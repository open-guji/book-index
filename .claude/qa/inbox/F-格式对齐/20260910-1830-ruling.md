## 病因（硬证据）

`book-text/README.md` 写 `text/*.md` 是「派生純文本（可重生成）」。但——

```
git show 89640c2      # 2026-09-05
夾註標記歸一：宋史藝文志 （（…））→ ⟨…⟩ 1,493 處
 43 files changed, 1335 insertions(+), 1335 deletions(-)
```

**那 43 个档全是 `collated_edition/juan/*.json`，一个 `.md` 都没改。**
⇒ 宋史藝文志 json 有 986 处 `⟨⟩` 而 md 是 0。

反过来，考补类那几部（`d59f2ofyy29s` 等）**校勘记只在 md 里**，
json 的 `sections[]` 里没有——那是另一条录入路径的产物。

## ⚠️ 关键约束：网站两份都读

`book-index-ui` 的 storage 层有两个口：

| API | 读什么 | 夹注怎么处理 |
|---|---|---|
| `getCollatedJuan(workId, juanFile)` | `juan/*.json` 的 `sections[]` | **`⟨…⟩` 在这里被渲染成 `<span class="bim-jiazhu">` 小字** |
| `getCollatedJuanText(workId, juanFile)` | `text/*.md` 原文 | 按原样 |

⇒ 宋史的 986 处夹注**只在结构化视图有**；考补类那 10,844 处校勘记**只在原文视图有**。
**两份都不是可以丢的那一份。**

## 本道的建议（不是裁决）

1. **判准按书而异，不要一刀切**：考补类以 md 为准补 json，宋史那类以 json 为准补 md。
2. **补齐要过闸**：补完之后两边的夹注处数与总字数必须相等，
   照本道那三道闸的第三道（夹注守恒）办。
3. **补齐先于转换**。任务书原话「转换脚本要是只改一边，两边会差得更远」——本道同意。

## 本道没做什么

**一个字都没改存量**（`book-text` 收工时 `git status` 干净）。
补齐不是本道写域（本道写域是 `guji-markdown` 全仓 ＋ 08 档 ＋ 新建的 scripts 目录）。
