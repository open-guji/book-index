# check：Entity Schema 文档三处枚举/前缀表与实测不符

## 一句话

`book-index-draft/SCHEMA.md` §4 Entity Schema 与 `qa_common.py` 的
`TYPE_PREFIX_OFFICIAL[Entity]` 有三处字典/枚举、一处 ID 前缀猜测，与全库实测不符。
本道写 `qa_entity.py` 时踩了个遍，都在自己文件里改过（不碰 SCHEMA.md/qa_common.py，
不在写域），但源头文档/共用表本身该更新，列在这里给协调者定后续。

## 1. `subtype` 缺 `collective`

SCHEMA.md §4 只列 `people | place | dynasty`。实测 production 有 42 条
`subtype: "collective"`，例 `hixhd2h9bv4m`「郵傳部」，其 `ai_note` 自述：
「此非個人，乃官署、局所、書院、編…」——是机构/官署类实体的既有合法分类。

## 2. `alt_names.type` 枚举缺至少 6 种

SCHEMA.md §4 列了 7 种（字/號/諡號/賜號/別名/常用名/簡體）。实测 production 里另有
（按出现频次）：`著錄形`(121)、`小字`(40)、`小名`(26)、`著錄原形`(21)、`法號`(20)、
`本名`(16)、`舊著錄形`(15)、`殘名`(13)、`異寫`(11) ……长尾还有 20 余种个位数值。
本道扫法：`qa_entity.py --batch official` 的 `ALT04` issue，`evidence` 字段即该值，
`by_code.ALT04` 从 2,166 降到 338（加了 6 种高频值后）。长尾没有继续追——跟
`qa_work.py` 的 `ROLE_PREFIXES`/`VALID_AUTHOR_ROLES` 一样，是个持续要扩的活字典，
不是一次能扩完的。

## 3. `external_ids.cbdb_match` 根本不是枚举

SCHEMA.md §4 写「auto | manual | none, optional」，读起来像三值枚举，实测是自由格式的
匹配凭据备注，例：`auto_create`、`auto_2026-09-06`、`manual (C5 batch17)`、
`manual_remap`、`auto_dy_unique`、`auto_dy_ambig_year`、`auto_placeholder_upgrade`——
一批就是几十种，共 3,394/30,875 条不在字面三值里。**建议 SCHEMA.md 这句话本身改措辞**
（"自由格式凭据备注，非枚举"），而不是继续拿窄字典去卡它。`qa_entity.py` 已经把
`check_external_ids` 里这条改成只验类型（须为字符串）。

## 4. `qa_common.TYPE_PREFIX_OFFICIAL[Entity]` 猜错

`qa_common.py` 原注释自己写「推测，待 promote Entity 后核对」，猜的是 `('11', '12')`。
现在核对了：

```bash
python3 -c "
import json,glob,collections
c=collections.Counter()
for f in glob.glob('book-index/index/entities/*.json'):
    for eid in json.load(open(f)): c[eid[:2]]+=1
print(c.most_common())
"
# → [('hi', 30875)]  —— 100%，没有例外
```

应改为 `('hi',)`。这条不改，`qa_work.py`/`qa_book.py`/`qa_entity.py` 只要跑
production Entity 都会 100% 报 `ID04` WARN（本道批量报告已把这条从逐条明细里摘出、
只留计数与样例，否则一个字段错误会把 24MB 的报告文件灌满同一句话）。

## 建议

四处都不在本道写域（SCHEMA.md、qa_common.py 均非「一个新文件 qa_entity.py」），
建议协调者定 owner：SCHEMA.md 三处文档更新 + `qa_common.py` 一处表更新，
改完后请 `qa_work.py`/`qa_book.py`/`qa_entity.py` 三边各自回归一遍。
