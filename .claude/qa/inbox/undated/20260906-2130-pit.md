# 坑：一次合流（`git merge`）把本道剛加之索引鍵靜默丟了

批十四推 main 後之下一次合流，`index/works/7.json` 之 diff 顯示「10 行刪除」，
其中恰刪去本道批十四新加之 `d59f6eq7hnnl`（紫霞洞琴譜）索引鍵——三方合併本應保留
雙方各自新增之鍵，此次卻把本道之新增鍵連著上游對同分片別處之改動一併吃掉了
（`entity.works 懸空` 由 0 變 1，方才查覺）。

已修復（重加索引鍵、同步一處連帶遺漏之 description 陳舊撰人稱）。

**通則（同坑9「合流後必重掃」之推廣）**：`verify.py` 之「entity.works 懸空」與
「索引檔缺記錄檔」二項，不能只在合流當下看一次——若合流本身之三方合併算法對
「新增鍵」與「同分片內他處之修改」共存時處理有誤，問題要等下一次 scan／verify
才會現形（本例：批十四推送時 verify 是 OK 的，問題出在下一次的 merge 動作本身）。
**每次 `git merge` 之後，除了跑 verify，若剛好新增過索引鍵，宜額外對該鍵單獨
`grep` 一次確認仍在**，不能只信任 verify 的彙總數字在推送前那一刻是綠的。
