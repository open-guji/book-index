## 五、只有我知道的（口头定过而未落纸者、以及看着该做其实不该做的事）

1. **断代原则的四条推论**（用户口头定，已写进录入规范但散在各处）：取内容主要创作之时（楚辞、礼记、
   大戴礼记据此收入）；口传之学取传授之始（公羊、穀梁、尔雅据此系先秦，**此条 2026-09-04 定案，
   注明「勿再议」**）；出土本墓葬年代是铁下限；注本传本从注者之世，白文另立节点承载先秦层。
2. **班固自注只否定不肯定**：注「依託也」「其語淺薄」者，只能否认旧题撰人，**不能据以定成书年代**。
   我曾据此误填《天乙》《務成子》为 pre-qin，被用户当场驳回（「非常怀疑」），已全部退回阙载。
   **同类切勿再犯**：小说家类混有武帝时、宣帝时之作，部类不能当断代之据。
3. **有无断链是可拆与否的分界**：《關尹子》隋唐志皆不著录、千年空白，故可拆出宋托名本；
   《鬻子》汉志→隋志→两唐志→崇文→四库著录链不断，**不可拆**（我拆过，被用户驳回后已并回）。
4. **「留在 Collection 标可疑」是用户定的处置**（2026-09-09）：《甘氏四七法》《養魚經》
   非汉志来源、是否先秦无从断定，**不移出**，将来展示时标可疑。**看着该移出其实不该移。**
   同类还有《黃帝長柳占夢》（仅汉志著录，成于西汉亦可能）。反面例子是《年歷帝紀》——
   撰人姚恭之「周」是北周误标为姬周，**这个该移出**，已移。
5. **index 显示朝代的规则**（全库 43,312 同／3,483 取 Work.dynasty／6 取 authors）：
   `Work.dynasty` 非空时优先，否则取 `authors[0].dynasty`。**只改 authors 而 Work.dynasty 非空
   的话，站上纹丝不动**——录入规范里原写的「index 层不读此字段」是错的，已订正。
6. **佚书 juan_count 是篇数当卷数**：《羋子》站上显示「十八卷」实为《汉志》十八篇。全库口径问题，
   **本道刻意没动**（等 schema 加 unit），谁要动请全库一次性来，别零敲。

   （「本库以今本与汉志本有文本承续，不作托名处理」这种要留）。
8. **溫浚源《漢書藝文志講要》已从全库 549 条 `description.sources` 删除**（用户定：已非实际来源）。

9. **我踩过没记进 PITFALLS 的坑**：解冲突脚本用 `git diff --name-only` 时，非 ASCII 路径被输出成
   八进制转义 → `json.loads` 崩；而后面 `git add -A && git commit` 是用 `;` 接的，照跑，
   **把 `<<<<<<<` 标记提交并推上了 main**（2026-09-07，约一分钟后修复）。此后每次 commit 前必跑
